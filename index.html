02Réalisation

Projet public : code et démarche consultables.

Analytics · Formule 1

De l'API Ergast à un dashboard d'analyse de courses

Les données de Formule 1 arrivent en JSON imbriqué, entassées saison après saison, telles quelles impossibles à croiser : comparer un pilote à un autre, un circuit à un autre, demandait de tout reprendre à la main.

La chaîne complète est en place : les données brutes sont ingérées par des jobs Spark, déposées dans un stockage objet, chargées dans BigQuery puis modélisées avec dbt (tables de staging, dimensions pilotes et constructeurs, table de faits des résultats). L'ensemble tourne sous l'orchestrateur Kestra, l'infrastructure est décrite en Terraform, et une vue consolidée alimente un dashboard Looker Studio pour analyser les saisons, les pilotes et les circuits.

  • Sources API Ergast (JSON imbriqué)
  • Traitement jobs Spark → NDJSON → stockage objet
  • Entrepôt BigQuery, modélisé avec dbt (staging, dimensions, faits, vues)
  • Orchestration Kestra, workflows versionnés
  • Infrastructure Terraform (bucket, dataset) et Docker
  • Restitution dashboard Looker Studio

05Comment on travaille

Quatre étapes, dans cet ordre, pour que rien ne reste flou.

  1. 01

    Cadrage

    Un appel pour comprendre vos données, vos contraintes et le résultat attendu. J'en ressors une proposition écrite, un périmètre et une estimation.

  2. 02

    Prototype sur vos vraies données

    Une première version fonctionnelle, sur un échantillon réel plutôt qu'un jeu de démonstration. C'est là qu'on découvre les vrais problèmes.

  3. 03

    Industrialisation

    Orchestration, tests, infrastructure décrite en code, suivi et alertes, documentation. Ce qui tourne doit pouvoir être réparé sans moi.

  4. 04

    Passation

    Session de passation avec votre équipe, dépôts rangés, décisions écrites. Vous restez propriétaires et autonomes sur tout ce qui est livré.
